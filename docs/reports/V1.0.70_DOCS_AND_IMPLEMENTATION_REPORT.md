## G. Network Routing

> **When the VPN tunnel is active, does the Server List update request use the VPN network only, without silent physical-network fallback?**

**CONFIRMED VPN-ONLY POLICY IN SOURCE. PHYSICAL VPN ROUTING NOT VERIFIED** (device unavailable).

- `routeLadder` returns `[TUNNEL, EMERGENCY]` when `tunnelUsable && hasBoundNetwork`, `[PHYSICAL, EMERGENCY]` otherwise.
- `fetchOnChosenPath` attempts exactly the chosen rung; a TUNNEL failure logs `no physical fallback (VPN active)` and returns null; a missing bound fetcher logs `tunnel unavailable (no bound VPN network); no physical fallback`.
- The v1.0.65 same-refresh downgrade and the opposite-rung fallback are **removed**.
- Source binding remains per-request `Network.getSocketFactory()`; never `bindProcessToNetwork`. A successful HTTP response is **not** treated as packet-path proof.

## H. Timeout and Protocol Priority

- Default **12 s**, min **8 s**, max **30 s**; a stored 31..60 clamps to 30 on read, 5..7 to 8, with no migration. Picker offers exactly 8..30.
- Default protocol order **SOFTETHER_UDP → SOFTETHER_TCP → MS_SSTP**; a stored user order still wins; an explicitly empty profile stays empty (refusal).
- Tests: `DataUtilTimeoutRangeTest`, `DataUtilDefaultsV1054Test`, `AutoModeControllerTest#defaultAttemptTimeoutMatchesTheSettingsDefault`, `AutoModeNativeBusyTest`, `DataUtilRoutingPreferenceRemovedTest`.

## I. Server Retention and Data Integrity

- Cap **500** via `capRetainedServers`, applied to both the fresh-observation merge and the fallback merge.
- Priority: `healthScore` → `connectOptions` count → `successCount` (history table) → `lastSeenAt` → `hostName` (deterministic).
- Manual/imported rows are **never** pruned; they occupy the cap first.
- A partial API response still never deletes stored rows (phase-1 retention preserved); the cap is the only removal path.
- Transaction boundary unchanged (`dao.replaceAll` is `@Transaction`); the history query is read-only.
- **Not verified:** DB/snapshot/UI count equality on a real device; real-SQLite migration coverage.

## J. Tunnel and Auto Connect State

- Attempt lifecycle and stale-attempt guards unchanged; no second competing tunnel is allowed (D-4 guard), so **make-before-break is not supported** — documented as a design limitation, not implemented.
- State reconciliation remains `GlobalVpnTracker` + `combineAutoModeState`; no single authoritative owner is declared (REQ-STATE-001 partial).
- Connection origin is **not persisted**; the UI synthesises `Connected (manual)`. Implementing it needs a storage decision (Room migration vs preference) — deferred.
