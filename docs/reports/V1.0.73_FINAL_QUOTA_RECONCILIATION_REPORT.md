## 11. Duplicate Import Semantics

SOURCE CODE EVIDENCE — the UI word "Imported" is `ImportOutcome.storedCount` = `stored.stored` =
**added + updated** (`ImportOutcome.kt:29`, `ManualImportStore.kt:166-172`). It is **not** "newly inserted rows":

- A duplicate host is an **update** (`current.containsKey(key)` → `updated++`, no slot consumed —
  `ManualImportStore.kt` update path; tests "a duplicate import consumes no quota slot", "an import that only
  updates is admitted even at the quota").
- Therefore the v1.0.72 duplicate-import message "Imported 5, rejected 0" means 5 rows were successfully
  processed (updated in place), and the JSON count staying 5 (not 10) is the persistence proof.

PRIOR PHYSICAL DEVICE EVIDENCE (v1.0.72, re-cited): duplicate re-import → "Imported 5, rejected 0", JSON
remained exactly 5. Combined with current source semantics, duplicate imports do not increase persisted counts.
No new import was performed (existing evidence sufficient).

## 12. Quota Message Call Chain

SOURCE CODE EVIDENCE — verified end-to-end in current source:

```
Manual add (ManualServerStore.addDetailed) or CSV import (SettingsScreen.runImport)
  → ConnectionListViewModel.importManualCsv (ConnectionListViewModel.kt:306)
  → ManualCsvImport.parse
  → ManualImportStore.addWithinQuota (ManualImportStore.kt:90)
  → ManualServerAdmission.admit — shared Mutex, count inside lock (ManualServerAdmission.kt:65-84)
  → QuotaAddResult / AddOutcome.QuotaReached
  → ImportOutcome (quotaReached / storedCount / rejectedCount)
  → SettingsScreen.runImport result handling (SettingsScreen.kt:278-298)
  → R.string.manual_server_result + R.string.manual_server_quota_reached
```

- Quota-full rejection: `manual_server_quota_reached` appended with real persisted numbers
  (`stored.manualCount`, `stored.quota`, `stored.totalCapacity` — no second, drifting query).
- Partially accepted import: updates always apply; only the un-granted new rows land in `quotaRejected`
  (`allowance = minOf(want, remaining)`), so the message reports exactly what happened.
- **Duplicate/update-only import at the quota is NOT reported as a quota failure**: `quotaRejected` counts only
  refused *new* rows; updates apply with `want == 0` → `allowance 0` → admitted, `quotaRejected = 0`
  (`ManualServerAdmission.kt:77`; covered by two dedicated tests, Section 14).

Classification: (1) source call chain **verified**; (2) automated result-path **verified**; (3) physical display
**NOT TESTABLE** (Section 15).

## 23. Final Recommendation

physical display caps the verdict). The quota (450 of 500) is enforced at the persistence boundary by a
process-wide Mutex across both Room and JSON surfaces; duplicate and update-only imports never consume slots and
are never misreported as quota failures; over-cap users retain edit/delete; no partial writes occur; full
regression and the 19 boundary tests are green and identical to baseline; lint introduces nothing new; device and
user data are untouched. Do not manufacture 450 records, add debug shortcuts, or bypass security to convert the
two remaining NOT TESTABLE / NOT OBSERVABLE items — they are honest, documented limitations, not defects. If the
2026-10-24/25 historical crash/ANR entries ever need explanation, run a separate targeted triage phase.
